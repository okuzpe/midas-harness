# Migration — 3.0.0 (role + paths; v1 layouts refused)

Midas 3.0 drops in-tree support for 1.x classic / compact / hub product trees.

## Who this affects

- **Already on v2 (`.harness/`)** — run `npx github:okuzpe/midas-harness#v3.0.0 update --yes`.
  Additive state field: `role: product` (installer writes it on fresh installs; doctor treats
  missing `role` plus `.harness/state.yaml` as product).
- **Still on 1.x classic / compact / hub** — 3.x **refuses** `update` / `--migrate` with **zero writes**.
  Pin **2.10.3**, migrate there, then upgrade:

```powershell
npx github:okuzpe/midas-harness#v2.10.3 update --yes
npx github:okuzpe/midas-harness#v3.0.0 update --yes
```

## Contract

- Discriminator is `role: engine | product` plus `paths:`. `layout:` remains a derived alias
  (`engine` → `classic`, `product` → `harness`) for adapter path selection.
- Removed: `scripts/migrate-layout.mjs`, `cli/migrate-harness.mjs`, `cli/lib/steps/migrate.mjs`.
- Kept: `scripts/lib/migrate-state.mjs` (state-field ledger, not layouts).
- Removed deprecated alias skills: `/midas-update`, `/midas-autopilot`, `/midas-auto-sprints`,
  `/midas-improve-loop`.
